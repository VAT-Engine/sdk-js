# Shared SDK requirements for public development

**Status:** Development baseline for review. Use the pinned OpenAPI and the [execution plan](../MD/IMPLEMENTATION_PLAN.md) for supported operations and milestone status.

- Gate A covers the direct HTTP client. Gate B covers optional durable request delivery. Complete acceptance independently. Follow the approved SDK release policy.
- Preserve all pinned CORE operations, including operations without an operation ID. Identify each by HTTP method and path. Preserve exact int64 values, string amounts, ordinary floats, nullability, and the distinction between omission and explicit false. Preserve download bytes, including JSON archive artifacts. Keep cursors opaque.
- Use the documented key scopes and environments. Where strict context is offered, enroll the expected binding from a trusted source, verify account and environment before a write, and send the expected-context assertion with the same protected mutation. Fail closed on failed preflight. The direct client may expose context discovery independently of strict mode. Gate B requires verified context.
- Keep explicit agent registration and claim as caller-invoked operations. Preserve approval, expiry and the documented pending interval. Keep claim tokens and returned credentials out of logs and fixtures. Avoid automatically repeating ambiguous registration.
- Keep direct retries bounded and operation-specific. Pin the original key, destination and semantic request for a logical invocation. Use an unknown outcome when safe replay is unavailable. A calculation replay requires valid idempotency identity, explicit transaction date, original inputs and attribution. Supply replay preserves account, identity, facts and event revision. A queue owns its delivery retries and uses a single transport attempt per dispatch.
- Normalize supply references using documented backend-compatible whitespace semantics. Validate the normalized UTF-8 string (maximum 160 bytes, with NUL and malformed input rejected). Apply generated schema validation after these checks if used. Compute local deduplication only after validation. Verify boundaries for ASCII, two-byte and four-byte text, including padded valid input, through the SDK entry point.
- Capture transaction-time facts before durable enqueue. Persist jobs and dedupe state before delivery, freeze request bytes before dispatch, and preserve stable receipts and dependencies across retries and upgrades. Preserve context and pause an uncertain job instead of redirecting it.
- Keep all VAT and filing decisions with the API. Clearly distinguish previews, persisted calculations, committed evidence and filing readiness. Document unsupported features and release evidence accurately.
